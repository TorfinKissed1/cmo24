# cmo24.ru: статическая версия лендинга

Одностраничный сайт «Центр механизированной отделки»: стяжка пола и штукатурка стен. Статика без сборки,
открывается на GitHub Pages. На хостинге страница переносится в тему WordPress, разметка и стили
остаются те же.

## Как открыть

```
python -m http.server 8790 --bind 127.0.0.1
```

и в браузере `http://127.0.0.1:8790/`. Открывать через `file://` нельзя: спрайт иконок и шрифты
подключаются по относительным путям, браузер их так не отдаёт.

Цвета взяты с логотипа-образца заказчика: тёмно-синий `#071f47` и оранжевый на кнопках и ценах, светло-серые
подложки. Подача сверена с лендингами бригад под Директ (pol.msk.ru, пластер.рф, pol-polych.ru,
expressevroservice.ru, вровеньпол.рф). Классы по БЭМ, все цвета, размеры и отступы через переменные в
`css/base.css`: отступ секций, отступ под заголовком, поля карточек и зазоры сетки одни на всю страницу.
Брейкпоинты: 1240, 1100 (меню уходит в бургер), 1024, 768, 480, 340.

Первый экран: фото на всю ширину, заголовок с ценой и три плашки, внизу белая панель с короткой формой
(переключатель «Стяжка / Штукатурка», поля с подписью внутри рамки, кнопка в одну строку).

На компьютере (от 1101 px) значки мессенджеров в правом нижнем углу видны, когда первый экран ушёл из вида и
пока не видны контакты или подвал; на 1101-1480 у секций шире поля, чтобы значки не легли на контент. До
1100 px вместо них нижняя панель «Позвонить / Telegram / WhatsApp / MAX», под неё у страницы отступ
(`page--with-bar`).

Иконки правятся в `img/icons.svg`, потом `python -X utf8 D:\jukov\tools\inline_icons.py` встраивает их в
HTML (`build_pages.py` вызывает его сам). Новая иконка в разметке пишется ссылкой `<use href="img/icons.svg#id">`
и после запуска скрипта становится встроенной.

3D-разрез. Толщина слоёв на сцене нарисована в 2,5 раза крупнее, иначе 5 см стяжки не разглядеть. Колесо
мыши и щипок не приближают сцену (иначе прокрутка страницы над ней застревала бы), вертикальный свайп по сцене
листает страницу, горизонтальный поворачивает разрез. До 1024 px сцена в обёртке `razrez__dock` приклеена под
шапкой, чтобы ползунок и разрез были видны вместе; цена там дублируется плашкой на сцене. Без WebGL вместо сцены текст, цена считается и так.
Сборка three.js лежит вне репозитория, в `D:\jukov\tools\three`: в `entry.js` перечислены нужные классы,
`npm run build` (esbuild 0.28.2) кладёт файл в `js/vendor/`. Новая версия three.js получает новое имя файла:
старое браузер держит в кеше.

Блок объектов описывает типы объектов и состав работ, а не конкретные сданные объекты: реальных фото с
площадью и сроком пока нет.

## Формы

Три формы, у каждой своя страница «спасибо» и своя цель Метрики:

| Форма | Где | Поля | Цель | После отправки |
|---|---|---|---|---|
| короткая | первый экран | вид работ, имя, телефон | `form_short` | `html/spasibo-korotkaya.html` |
| средняя | «Расчёт стоимости» | то же и площадь | `form_medium` | `html/spasibo-srednyaya.html` |
| длинная | «Контакты» | то же и толщина (стяжка) или материал стен (штукатурка) | `form_long` | `html/spasibo-dlinnaya.html` |

Толщина и материал стен не обязательны. Телефон уходит в виде `+79991234567`. Ошибку поля показывает цвет:
подпись, подсказка и рамка краснеют, текст ошибки скрыт и читается только экранным чтецом.

Кнопки «Рассчитать стяжку / штукатурку / похожий объект» ведут к синему блоку с формой (`#raschet-forma`) и
отмечают в ней вид работ.

**Отправки пока нет.** У форм нет `data-endpoint`, поэтому после проверки в браузере они сразу ведут на
страницу «спасибо». На хостинге форме ставится `data-endpoint` с адресом обработчика: тогда скрипт
шлёт `POST` с полями формы и переходит на «спасибо» только при ответе 200.

Обработчик на сервере обязан проверить всё заново, браузеру не доверять: приманка `company_website`
(заполнена: ложный успех), CSRF, отметка захода и 3 секунды с открытия страницы, лимит заявок с IP,
нормализация телефона. Порядок проверок и числа: `~/.claude/rules/zashchita.md`.

## Цели Метрики

Ссылки с `data-goal`: `click_phone`, `click_tg`, `click_wa`, `click_max`, `click_max_bot`. Цели
срабатывают, когда на странице есть счётчик и задан `window.YM_COUNTER` с его номером. Счётчика пока нет.

## Заглушки, которые надо заменить

- Фото объектов, преимуществ и гарантии сгенерированы. Появятся реальные объекты с площадью и сроком:
  вернуть в «Объекты» табличку «площадь, срок, стоимость».
- Телефон, почта, мессенджеры и реквизиты взяты с прошлого сайта заказчика 24styazhka.ru.
- Счётчик Метрики.
- Цена в 3D-разрезе: только цены «от» с карточек услуг, умноженные на площадь. Надбавок за толщину,
  утеплитель и сетку нет, пока нет цифр.

## Выкладка

GitHub Pages из ветки `main`, корень репозитория. После правки CSS или JS поднять версию в ссылках
(`base.css?v=10`) в `index.html` и `VERSION` в `build_pages.py`: иначе телефон покажет старый файл из кеша.
